# 智能体架构与课程实验知识

## 智能体基本流程

智能体不是固定脚本，而是由大模型根据用户需求动态决定下一步动作的程序。典型流程包括：

- 理解需求：识别用户真正要查询什么，区分单点查询和完整规划。
- 拆解任务：把复杂需求拆成天气、交通、地点、预算、住宿等子任务。
- 调用工具：在需要真实数据时调用外部 API 或本地工具。
- 汇总结果：把工具结果交给大模型综合判断。
- 自动修正：当工具失败或结果不足时，说明限制并使用可用的回退策略。
- 输出成品：生成可执行的方案，并提供结构化数据给前端卡片展示。

## LangChain 的作用

LangChain 适合构建 Agent，因为它提供了模型封装、工具注册、消息历史、Agent 执行链和回调/流式事件能力。项目中 LangChain 主要承担：

- 统一接入 DeepSeek 的 OpenAI-compatible API。
- 将 Python 函数注册为 Agent 可调用工具。
- 让模型根据用户意图自主选择工具。
- 保留多轮消息上下文。
- 通过流式事件展示模型阶段和工具调用阶段。

## RAG、Memory、Skill 的区别

- RAG：从外部知识库检索资料，再交给模型回答。适合课程资料、城市攻略、开放时间、避坑建议、项目说明文档等静态知识。
- Memory：保存用户或会话上下文。适合记住用户之前说过的出发地、预算、偏好、历史会话。
- Skill：把某类稳定能力封装为可复用步骤或工具。适合“生成旅行方案”“查询交通”“写实验报告”等可复用技能。

## 本项目的 RAG 使用原则

本地 RAG 只提供静态知识补充，不替代实时 API。实时天气、交通、酒店、航班、火车票仍应优先调用对应工具。

适合调用 RAG 的场景：

- 用户询问智能体架构、LangChain 优势、RAG/Memory/Skill。
- 用户询问课程实验说明或项目实现思路。
- 用户需要城市旅行背景、避坑建议、适合人群、路线组织经验。
- 外部 API 无法覆盖的主观攻略类问题。

不适合只依赖 RAG 的场景：

- 明天的天气、空气质量、预警。
- 实时路况、公交换乘、航班、高铁余票。
- 酒店实时价格和库存。
